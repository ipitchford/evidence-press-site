This is an audio briefing from Evidence Press on a research candidate about counting the ways to cover a network.

A dominating set in a network is a set of nodes such that every node is either in the set or directly linked to one that is, like placing guards so that every site is watched. Count the dominating sets of each size and you get a sequence of numbers. In every network anyone had checked, this sequence climbs to a single peak and then falls. Alikhani and Peng conjectured that this always happens, and the question was still listed as open.

This candidate shows that the conjecture is false. It builds two explicit connected networks, each with 317,440 nodes. In both, there are more dominating sets of size 160,080 than of size 160,320, and more again of size 160,560 than of the middle size. So the count dips and then rises again, and an exact integer calculation proves all three comparisons.

The idea is to build two large families of dominating sets that have exactly the same number of members but different typical sizes, while every other dominating set is comparatively rare. The sizes then form two humps, and the count dips in between. The same idea gives networks with many separate peaks, and networks in which the most common size sits far from the average size, which answers a question of Beaton and Brown. In the other direction, if every node has a little more than the base-two logarithm of the number of nodes as its number of neighbours, the sequence does have a single peak, exactly at the middle.

The limits are clear: the example is large and has not been minimised, the exact degree threshold for a single peak is still open, and the question for trees remains open.

This is an unrefereed candidate, checked by internal AI-assisted review and exact computer arithmetic rather than by peer review, and this briefing uses a synthetic voice that is not additional evidence.
